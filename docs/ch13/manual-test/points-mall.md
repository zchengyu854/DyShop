# 积分商城模块 — 手工测试清单（Manual Test）

> 模块：ch13 积分商城 · 依据 `docs/ch13/spec.md` v1.0
> 环境：`docker exec mysql-dev mysql -uroot -p…`（无本机 client）；前端本地起 dev server；需要 A（普通用户）、B（会员）两账号与 admin 后台账号。

## 1. 后台商品管理

- [ ] 新建 COUPON 商品：关联启用中模板、积分价 500、库存 100、限兑 1 → 保存成功；未关联模板 → 校验拒绝
- [ ] 新建 CODE 商品：积分价 800、库存 -1 不限 → 保存成功
- [ ] 编辑商品（改名/改积分价/改库存/改排序）成功；已产生兑换记录的 COUPON 商品改关联模板 → 拒绝
- [ ] 下架商品 → C 端商城不可见；上架 → 恢复可见
- [ ] 删除限制：上架中删除拒绝 / 下架后删除成功（逻辑删除，兑换记录保留）
- [ ] 兑换记录页：按商品/用户名关键字分页查询正常

## 2. 积分余额与批次

- [ ] A 账号完成一笔已支付订单（确认收货）→ `user.points` 增加 `floor(pay_amount)×倍率`；`point_batch` 新增一条（remaining=本次积分、expire_at=到账+12 个月）；`point_log` 一条
- [ ] 重复确认收货 → 不重复发放（幂等）
- [ ] 个人中心积分卡片显示余额；`GET /api/user/member/points` 流水正确

## 3. 商城兑换（COUPON）

- [ ] A 打开积分商城：在售商品可见（封面/名称/积分价/库存/限兑），余额充足 → 兑换按钮可点
- [ ] 点击兑换 → 确认弹窗 → 确认成功：券包「未使用」出现该券（来源=积分兑换）；余额 = 原 − 500；流水记 -500；兑换记录一条
- [ ] 再兑同模板另一商品/同一商品 → 409「已兑换过该商品」
- [ ] B（余额不足）兑换 500 积分的商品 → 页面置灰「积分不足」；直接调接口 → 409
- [ ] 兑换的券在结算页可选可用（金额/门槛与模板一致）

## 4. 商城兑换（CODE）

- [ ] 兑换 CODE 商品成功 → 返回唯一 16 位卡密，页面展示 + 一键复制
- [ ] 同商品二次兑换 → 409
- [ ] 兑换两次不同 CODE 商品 → 卡密互不相同（uk_code 生效）

## 5. 库存与限兑

- [ ] 库存限 1 的商品：A 兑换后库存 0 → C 端显示「已兑完」，B 兑换 → 409「已抢光」
- [ ] 并发：两账号同时兑换库存 1 商品 → 恰一人成功
- [ ] limit_per_user=2 的 CODE 商品：同人兑 2 次成功、第 3 次 409

## 6. 积分过期任务

- [ ] 手工造数据：`INSERT INTO point_batch (user_id,'ORDER',order_id,points,remaining,expire_at) VALUES (A,'ORDER',99999,1000,1000, DATE_SUB(NOW(),INTERVAL 1 DAY))` → 触发任务（或调用任务方法）
- [ ] 任务后：该批次 remaining=0；`user.points` = 有效批次和（同步扣减）；`point_log` 记「积分过期」-1000
- [ ] 再次运行任务 → 0 副作用（幂等）
- [ ] 过期批次不影响商城兑换可用余额；有效批次 FIFO（先到期的先扣）

## 7. 回归

- [ ] ch12：退款后消费/等级扣减不受影响

- [ ] 前端构建通过、页面无报错
