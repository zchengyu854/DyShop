## 1. 阶段划分

### P0 准备与表结构（P0-ready）

- 产出：DDL 迁移脚本（`coupon_template`、`user_coupon`、`order_coupon` + `orders.discount_amount` + 索引/唯一约束）；后端实体与 Mapper（沿用项目现有 ORM 风格）。
- 关键：`user_coupon` 唯一键 `(user_id, template_id, source)`；`order_coupon.order_id` 唯一；`user_coupon.used_order_id` 索引。
- 验收：迁移脚本可重复执行（幂等）；实体/表字段对齐 spec §3。

### P1 后台：模板管理 + 发放 + 用户券管理

- 产出：后台 API（spec §4.1）与后台前端页面（模板列表/表单、发放弹窗、用户券列表/作废）。
- 关键规则：编辑限制（amount/scope/valid 仅新领取生效）、停用不影响已发券、逻辑删除仅限停用模板、发放幂等（同源同人存在时 409）。
- 验收：建券 → 发放指定用户/全员 → 用户券列表可见且状态正确。

### P2 C 端：领券中心 + 我的优惠券

- 产出：C 端 API（spec §4.2 前三项）与页面（领券中心、我的优惠券三态列表）；侧栏菜单 `frontend/src/config/userMenu.js` 的「我的优惠券」占位项改为指向新路由。
- 关键规则：领取事务（每人限 1、总量乐观锁防超发、有效期计算 §5.6）、重复领取 409。
- 验收：领取成功后「我的券」可见；总量耗尽提示「已抢光」。

### P3 结算集成：预览算价 + 下单扣券

- 产出：`/api/orders/preview` 支持 `couponId`（叠加会员折扣、返回券抵扣与应付）；`POST /api/orders` 支持 `couponId` 且事务内乐观扣券（spec §5.3）；结算页选券 UI（单选、门槛提示、实时重算、清缓存）。
- 关键规则：一单一券（`order_coupon.order_id` 唯一兜底）；`pay_amount = total_amount − discount_amount ≥ 0`；`discount = min(券额, 适用小计)`；范围「分类 ∪ 商品」并集生效（scope=LIMITED 至少一项非空）；allow_stack=0 时命中会员折扣商品则整单不可用。
- 验收：ALL 与 LIMITED（分类 ∪ 商品并行）各自正确判定门槛与抵扣；会员 + 券组合（allow_stack=1）算价正确；并发抢同一张券仅一单成功。

### P4 回退与定时任务

- 产出：手动取消 / 超时任务回退券（spec §5.4，幂等、保留原有效期、已过期置 status=2）；可选：批量过期券清扫。
- 关键规则：与库存回补、积分回补同事务；重复执行 0 行副作用。
- 验收：取消/超时订单后券回到未使用且有效期不变；重复取消不重复退券。

### P5 联调与手工验收

- 产出：前后端联调修复；按 `manual-test/coupon.md` 全量过一遍；回归 ch07/ch09/ch10 相关用例（结算、会员价、订单列表快照展示）。
- 验收：spec §9 验收标准全绿。
