# 售后/退款模块 — 实施计划（Plan）

> 模块：ch12 售后 · 基于 `docs/ch12/spec.md` v1.0

## 阶段划分

| 阶段 | 内容 | 验证 |
|---|---|---|
| P1 数据层 | after_sale 表迁移 + 实体/Mapper + OrderItemVO 补 id | 迁移执行 + 编译 |
| P2 后端 | C 端申请/列表/详情/取消 + 后台列表/同意/拒绝 | curl 联调（含 409/幂等/金额） |
| P3 前端 | 我的售后页 + 申请入口 + 后台审核页 + 菜单 | npm run build |
| P4 验收 | 全链路联调 + 手测文档回填 | 见 manual-test/after-sale.md |

## 关键决策

- 退款金额**自动计算**（order_item.price × quantity），用户不可改，前端只读展示 —— 防改价纠纷。
- 售后不触碰原订单（订单保持已完成），售后单独立状态机 —— 与 ch07 订单解耦，回归风险低。
- 同意即模拟退款完成（status=2）—— 与 ch07 模拟支付一致，无真实打款通道。
- 同一 order_item 唯一售后（数据库唯一索引兜底 + 业务预检 409）。

## 风险与对策

| 风险 | 对策 |
|---|---|
| 订单列表/详情已有 UI 结构复杂 | 先读 OrderDetail/OrderList 再最小侵入加「申请售后」入口 |
| 快捷操作区入口位置 | 读 AccountOverview 组件确认配置化方式，接入「售后/退款」 |
| 重复申请并发 | order_item_id 唯一索引 + DuplicateKeyException 转 409 |

## 里程碑

- M2：P3 完成（前端可用）
